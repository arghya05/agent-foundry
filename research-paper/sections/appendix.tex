\section{Ablation definitions}
\label{app:ablations}
Ablations patch runner-owned objects after setup (\evpath{benchmarks/agentgovbench/ablations.py}); the production control plane has no ablation flags. \emph{Delegation attenuation}: delegated scopes ignored. \emph{Delegation chain}: chain omitted from audit. \emph{Principal rate limiter}: limiter always admits. \emph{Locally declared fail mode}: fail mode learned only from successful reads (the original design). \emph{Honor fail-closed}: outages always fail open. \emph{Tenant membership}: a principal known in any tenant is accepted in every tenant. \emph{Deny-overrides}: the first defined rule in the order user--tool, user, tool, default wins. \emph{Per-call policy read}: a policy snapshot from setup is used. \emph{Decision audit}: no audit records. \emph{Plane scope check}: the control plane's required-scope check is removed while the gateway PDP keeps its own. \emph{All scope checks}: both removed. \emph{Tier rules}: every tier resolves to allow. \emph{Anonymous principal}: an empty uid is replaced by a member principal. The two probes, \emph{deny-everything} and \emph{allow-and-audit}, bypass enforcement entirely but still write audit records through the plane's recorder.

\section{Anti-vacuity checks}
\label{app:av}
For each official scenario the harness records the number of attempted calls, audited decisions, allowed calls and, for runners that expose them, executed tool effects. \emph{Decision coverage} holds if attempts $>0$ and decisions $=$ attempts. \emph{Effect fidelity} holds if executed effects $=$ allowed calls, so an allowed decision that never ran the tool, or an effect without an allowed decision, is detected. \emph{Liveness} applies to scenarios whose expectations include \code{tool\_allowed} or \code{rate\_limited\_count} and holds if at least one call was admitted; it rejects a deny-everything system on exactly the scenarios whose upper-bound assertions it otherwise passes. These checks are reported beside, not inside, the official score.

\section{Scenario-level vacuity}
\label{app:vacuity}
Of the \AGBTotal{} official scenarios, \VacuousAny{} are passed by at least one of the four trivial runners (no governance, audit-only, deny-everything, allow-and-audit) and \VacuousNone{} by none. The non-vacuous scenarios are those that require an allowed and a denied outcome for different principals, tools or times within one scenario (for example, a user override that allows one principal while denying another). A benchmark that wants per-scenario diagnostic value, rather than only an aggregate, benefits from pairing each deny expectation with an allow expectation that a constant policy cannot satisfy.
