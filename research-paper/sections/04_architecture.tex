\section{Architecture}
\label{sec:architecture}
\input{figures/architecture.tex}
\method{} is a Python package (\code{agent\_foundry}, 61 modules) whose base install depends only on \code{cryptography}; every integration (LangGraph, LangChain, model providers, MCP, Redis, Postgres, Chroma, OPA/Cedar, OpenTelemetry, LiveKit) is an optional extra. Figure~\ref{fig:architecture} shows its layers. We describe each by its responsibility, its interface, and the \gec{} obligation it discharges, then explain the design decisions that differ from common practice.

\subsection{Layers}
\paragraph{L0 Entry and configuration.} An agent is defined once, imperatively (\code{Agent(\ldots)}) or declaratively (\code{AgentSpec} from YAML/JSON with structured tool metadata and named critique evaluators), and exposed through \code{run}/\code{arun}/\code{stream}/\code{resume}/\code{batch}, a CLI, an HTTP/SSE server with a browser console, a Slack channel and an A2A bridge. Every public entry point is wrapped by \code{scoped\_execution}, which converts an \code{ExecutionContext} into the request scope of \S\ref{sec:formal}. This is where controls enter; lower layers read them from the scope rather than from parameters (direct graph-state callers retain an older state-key interface, which the resolvers also honor).

\paragraph{L1 Orchestration.} A turn runs \emph{think} (prompt assembly and a model call), \emph{act} (tool calls, dispatched concurrently where independent), an optional \emph{self-verify} revision, and \emph{critique}, a KPI-scored gate that retries with more evidence, asks a clarifying question, or escalates to a human. Six multi-agent topologies---supervisor, swarm (handoffs), blackboard, debate, fan-out and DAG---reuse the same per-agent configuration, so governance, budgets and critique apply to every specialist.

\paragraph{L2 Runtime seam.} Execution is a \code{WorkflowEngine} protocol (\code{build}, \code{run}, \code{stream}, \code{resume}) selected from a registry. Two engines implement it: a from-scratch native loop, and a LangGraph \code{StateGraph} engine for LangGraph's checkpointing and interrupts. The same configuration runs on either, which enables the differential testing of \S\ref{sec:conformance}. Native single-agent state persists through versioned \code{StateStore}s (in-memory, SQLite, Redis, Postgres) with optimistic version checks.

\paragraph{L3 Tool effects.} The \emph{control plane} (\code{control\_plane.ControlPlane}) is the multi-tenant admission point of \S\ref{sec:formal}: tenant policy documents re-read per call, tier-aware rules with deny-overrides, per-principal sliding-window limits, attenuating delegation, a locally declared fail mode, and one audit record per decision. Admitted calls execute through the \emph{governed tool gateway} (\code{GovernedToolGateway}), which requires a trusted user and tenant on every call, re-applies the policy decision point (allowlist, declared scopes, data classification, optional OPA or Cedar engine, egress allowlist, approval), enforces budgets and JSON-Schema validation of inputs and outputs, binds idempotency keys to principal and payload, and audits admission and results. MCP servers' tools enter as ordinary tool specifications and are governed identically.

\paragraph{L4 LLM gateway.} Tasks route to ranked model lists with failover, a prompt cache whose key digests the complete request and the calling principal (I5), a rate limiter and per-call cost accounting. Model allowlists in the request scope narrow the candidate list; an empty intersection is an error, not a fallback to any model.

\paragraph{L5 Context.} Working, episodic, semantic, procedural, knowledge-graph and profile memories sit behind small protocols. A \code{ContextEngine} assembles prompt context by retrieval, ranking, filtering, compression and token budgeting. Retrieved passages and tool results are screened by the same injection detectors as user input; flagged passages are dropped and PII-redacted, flagged tool results are labelled untrusted (I6); knowledge chunks carry permission tags filtered by the caller's roles, and the tenant is taken from the request.

\paragraph{Rails.} The \emph{governance rail} provides identity, role-based tool access, six autonomy levels, input/output/action/runtime guardrails---including the trained injection gate of \S\ref{sec:security}---and audit sinks. The \emph{evaluation rail} provides a KPI board with LLM-judge, database-match and grounding scorers, and an evaluation gate that scores an agent against a versioned dataset and can fail a release; missing oracles are recorded as unmeasured and an empty gate fails (I7).

\subsection{Design decisions and their origin}
\label{sec:design}
We state which ideas are borrowed and which choices are, to our knowledge, specific to this design; \S\ref{sec:related} compares them with the closest systems.

\paragraph{Controls as scope, not arguments.} Capability systems~\cite{dennis1966programming,miller2006robust} and the principle of least privilege~\cite{saltzer1975protection} are old; the confused-deputy problem~\cite{hardy1988confused} is exactly the delegated-identity failure we observed. Our contribution is to apply them \emph{at every agent execution boundary}---sync, async, streaming generators, resume, threads, fan-out, DAG, batch, adapter exports---through one context-variable scope with a meet operation, so that adding a new boundary requires wrapping it, not threading a new argument through each layer. Streaming generators re-enter the scope at every step so that a consumer's own context is restored between yields.

\paragraph{Live handles are not state.} Checkpointing frameworks persist graph state; if a budget object or cancellation token is persisted, resume either loses it or resurrects a stale one. We keep them out of checkpoints and require callers to re-supply controls on resume, so a revoked role takes effect on the resumed run. This trades convenience (controls must be supplied again) for the property that persisted state can never widen authority. It also has a cost that CapLease~\cite{xu2026caplease} and ResidualAuth~\cite{choi2026residualauth} make precise: state that must \emph{narrow} authority across resume, such as a consumed single-use approval or a revocation history, cannot be re-derived from the request and needs a durable, monotone store. \method{} does not yet provide one; its approvals are re-checked on resume against current policy but are not single-use.

\paragraph{Deny-first, single admission.} A decision pipeline that checks approval before hard policy lets approval override policy; we observed this in the original code. The PDP and the control plane evaluate unconditional denials before approval requests, and rate limiting is evaluated last so that denied calls do not consume capacity (Thm.~\ref{thm:rate}).

\paragraph{Fail mode is deployment configuration.} Proposition~\ref{prop:failmode} shows that a fail mode stored only in the policy source cannot be honored for a tenant first seen during an outage. We found this empirically before proving it.

\paragraph{Unmeasured is not passed.} Evaluation harnesses often default a missing oracle to success or drop failing cases. \method{}'s gate distinguishes \emph{failed}, \emph{unmeasured} and \emph{passed}, and our benchmark harnesses keep runner exceptions and interrupted attempts in fixed denominators. The same principle motivates the anti-vacuity checks of \S\ref{sec:vacuity-def}.

\paragraph{Engine neutrality as a test oracle.} Supporting two engines is common. We use the second engine as a \emph{differential oracle}: identical scenarios run against both, and any divergence in control outcomes is a defect in one of them, as in differential testing~\cite{mckeeman1998differential}. This found the native delegated-identity bug that single-engine tests had not.
