# Agent Foundry — Deep-Dive Q&A Index

**54 modules · 826 interview-grade questions**, one folder per module, each answer grounded in a full read of the actual source (function/class names, line numbers, real behavior — not marketing copy). This is interview/deep-dive prep: the goal is to be able to defend every design decision in this codebase under hard questioning, including the decisions that turned out to have real bugs or unfinished edges. Every module folder is honest about what it does badly, not just what it does well — glossing over a weakness here is worse than useless for prep.

Generated by reading each file in full and writing 12–20 Q&A pairs per module across 8 parallel review passes, one per architectural layer below.

## 1. Core Execution Engine
How a single agent step runs, how engines abstract over runtimes, and the run/cancellation lifecycle.

- [core_agent](core_agent/README.md) — `Agent`/`Workflow` entry points; the "add a runtime with zero core changes" claim holds for `Agent` but not `Workflow`'s hardcoded runtime tuple
- [core_engines](core_engines/README.md) — LangGraph vs. Native `WorkflowEngine.build()`; a new config field can silently no-op on LangGraph but "just work" on Native
- [core_native_engine](core_native_engine/README.md) — the native (non-LangGraph) think/act loop; an LLM timeout mid-`_think()` can leave state inconsistent
- [core_native_orchestration](core_native_orchestration/README.md) — native multi-agent topologies + HITL pause/resume; abandoned paused threads leak memory with no TTL
- [core_execution_context](core_execution_context/README.md) — cross-cutting execution context, incl. `CancellationToken`; real documentation/implementation drift found
- [core_run](core_run/README.md) — the `Run` lifecycle wrapper; a real race where `Run.cancel()` gets silently clobbered by an in-flight completion
- [core_protocols](core_protocols/README.md) — the core interfaces everything implements against; a `run_id`/`thread_id` naming bug in `StateStore.load()`

## 2. Runtime, Models & State
The Runtime axis, model routing, registries, durable state, and eval gating.

- [runtime](runtime/README.md) — budgets/circuit breaker/rate limiter/SLA tracker; none of them are thread-safe, an undocumented precondition
- [core_model_router](core_model_router/README.md) — routes tasks to ranked model lists; a deliberate determinism-over-adaptivity tradeoff vs. LiteLLM-style dynamic routing
- [core_registries](core_registries/README.md) — tool/version registries; a stringly-typed `"current": str(v == current)` bug that's always truthy
- [core_result](core_result/README.md) — the `RunResult` type; a missing-deepcopy mutation hazard on `messages`/`raw`
- [core_state_store](core_state_store/README.md) — durable state persistence incl. Postgres; the recent SQL-injection fix, the lock-scope fix, and a remaining unlocked-connection gap
- [core_tool_decorator](core_tool_decorator/README.md) — the `@tool` decorator; its `timeout=` kwarg never syncs to `ToolSpec.timeout_s`
- [core_evalgate](core_evalgate/README.md) — eval-gate scoring; crashed trajectories get counted as trajectory *passes*

## 3. Multi-Agent Orchestration
Coordinating multiple agents: shared memory, channels, planning, escalation, distribution, batching.

- [orchestration](orchestration/README.md) — governed multi-agent turns; a reproduced live bug where a tool-approval interrupt gets silently swallowed
- [blackboard](blackboard/README.md) — shared blackboard memory; not part of the durable, checkpointed graph state
- [channels](channels/README.md) — Slack/inter-agent channels; ack timing vs. platform retries can double-process a turn
- [planning](planning/README.md) — task/plan decomposition & KPI scoring; `score()` and `_ranked_score()` can disagree on the same input
- [escalation](escalation/README.md) — human-in-the-loop escalation; `Escalator` is fully built but never wired into the actual tool-call gate
- [distributed](distributed/README.md) — distributed execution across workers; the idempotency store has no in-flight marker, enabling duplicate destructive execution
- [batch](batch/README.md) — batch run processing; a paused/escalated run can be silently reported as a successful result

## 4. Interop Bridges & Tooling
Talking to other agent frameworks and exposing/consuming tools.

- [a2a_bridge](a2a_bridge/README.md) — Google A2A protocol bridge; a Task-validation ordering bug lets malformed data reach the client
- [autogen_bridge](autogen_bridge/README.md) — AutoGen bridge; `asyncio.run()` inside a sync call is a deadlock hazard under async dispatch
- [crewai_bridge](crewai_bridge/README.md) — CrewAI bridge; a mismatched `input_key` silently interpolates the wrong (or no) variable
- [mcp_tools](mcp_tools/README.md) — MCP tool integration; a timed-out connect leaks the background thread and subprocess
- [tools_gateway](tools_gateway/README.md) — the generic tool registry/gateway; `invoke()` admits in its own docstring that it bypasses PDP governance checks
- [http_tools](http_tools/README.md) — HTTP-based tool calling; `egress_hosts` derivation and unrestricted redirect-following both have SSRF-adjacent gaps
- [data_connectors](data_connectors/README.md) — external data connectors; `allowed_tables` is a naive lowercased substring match, not a real SQL parse

## 5. Safety, Security & Governance
Guardrails, policy, sandboxing, contracts, flags, and versioning.

- [guardrails](guardrails/README.md) — input/output guardrails; a second-order prompt-injection attack against the guardrail judge itself
- [security](security/README.md) — `CredentialVault`/`EgressPolicy`/PDP/audit; egress checks validate declared hosts, never the actual runtime destination
- [policy_engine](policy_engine/README.md) — the policy decision point (built-in/OPA/Cedar); `decide()`'s `args` parameter is traced through and never actually used
- [sandbox](sandbox/README.md) — code execution sandboxing; two experimentally-verified findings — a timeout that doesn't actually time out on an infinite loop, and a shared-by-reference builtins dict that lets one sandboxed call permanently corrupt every future call in the process
- [contracts](contracts/README.md) — shared dataclasses (`ToolSpec`, `Policy`, etc.); `data_classification` is a bare string with no enum, so a capitalization typo silently disables a restriction
- [feature_flags](feature_flags/README.md) — the feature-flag provider; `bool`-vs-`int` in Python makes `set("x", True)` and `set("x", 1)` behave completely differently
- [versioning](versioning/README.md) — artifact/prompt versioning; read-only-looking calls (`get`, `history`) unconditionally create directories on disk, widening a path-traversal surface

## 6. Observability, Eval & Learning
Tracing, evaluation, real-time events, experiments, KPIs, and feedback loops.

- [observability](observability/README.md) — tracing/logging/metrics; where the "GIL makes span-append safe" argument actually breaks down
- [eval](eval/README.md) — the eval harness; a fragile session-matching convention that breaks silently if a call site forgets `session_id`
- [eval_dataset](eval_dataset/README.md) — eval dataset loading; a bare-string `forbidden_tools` silently becomes a set of characters via `frozenset(str)`
- [events](events/README.md) — the `EventBus` pub/sub system; distinct from `core_native_orchestration`'s actual Phase-4 streaming work — verified, not assumed
- [experiments](experiments/README.md) — A/B experiment infrastructure; changing variant weights mid-experiment silently reassigns already-bucketed users
- [kpi](kpi/README.md) — KPI tracking incl. `composite_grounding_kpi`; the real production incident behind excluding (not zero-scoring) a KPI's weight
- [reinforcement](reinforcement/README.md) — honestly, this isn't reinforcement learning at all — it's a feedback curation/export pipeline, with an unscoped session-filtering bug
- [benchmark](benchmark/README.md) — performance benchmarking; three distinct failure modes collapse into one indistinguishable `CaseResult`

## 7. Developer Experience & Interfaces
CLI, scaffolding, serving, context/memory, i18n, and the console UI.

- [cli](cli/README.md) — the command-line interface; `--spec` and a positional script aren't mutually exclusive in argparse, so passing both silently drops one
- [scaffold](scaffold/README.md) — project/agent scaffolding incl. `create_agent` (scaffold.py:97); unconditional `"w"`-mode writes can destroy a developer's filled-in TODOs on re-run
- [quickstart](quickstart/README.md) — quickstart/tool-conversion helpers; `to_langchain_tool` deliberately ignores declared parameters in favor of real type hints
- [serve](serve/README.md) — the HTTP serving layer; a documented real incident where an uncaught `BudgetExceeded` became an opaque browser-side failure
- [context](context/README.md) — actually a memory/RAG context-retrieval engine, not request-context propagation; ACL filtering is bypassable if a caller skips `ContextEngine`
- [i18n](i18n/README.md) — internationalization; why avoiding stdlib `locale.setlocale()`'s global mutable state is load-bearing correctness under concurrent requests
- [ui_console](ui_console/README.md) — the console/terminal UI; a stale-snapshot bug in `handle_interrupt`'s loop misses chained multi-step approvals

## 8. Specs, Prompts & LLM Gateway
Declarative agent specs, prompt templating/versioning, and the multi-provider LLM gateway.

- [agent_spec](agent_spec/README.md) — declarative agent specs, deliberately built without Pydantic; `resolve_tool()`'s documented arbitrary-import/execute attack surface
- [prompts](prompts/README.md) — prompt templating & versioning; the exact disk-level mechanics of "instant" rollback and the non-atomic multi-writer race it doesn't cover
- [llm_gateway](llm_gateway/README.md) — the unified multi-provider LLM gateway; a blanket `except Exception` in the failover loop treats a fatal auth error the same as a transient rate limit

### How to use this for interview prep
Each folder's `README.md` is self-contained: a one-line grounding description of what the module actually does, followed by 12–20 Q&A pairs ordered roughly from "explain the design" to "defend the edge case." Read a folder end-to-end before an interview touching that layer — the hardest question in each is flagged in this index so you can jump straight to it under time pressure. Several modules above have real, unfixed bugs (not hypothetical ones) documented with exact reproduction steps; know them cold, since "here's a bug I know about and here's exactly how I'd fix it" is a stronger answer than pretending the code is flawless.
